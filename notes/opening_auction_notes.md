# 开盘集合竞价撮合笔记

## 1. 集合竞价是什么

集合竞价是把一段时间内的买入、卖出申报集中起来，一次性确定一个统一成交价的竞价方式。开盘集合竞价的核心问题是：在所有可能价格里，选出一个最符合交易所规则的价格。

连续竞价则不同。连续竞价是一笔订单进来就尝试和对手方订单逐笔撮合，成交价由当时订单簿上的最优买卖价决定。

本项目研究的是开盘集合竞价。

## 2. order 和 trade 文件怎么理解

`order` 文件记录逐笔委托。常用字段包括：

| 字段 | 含义 |
| --- | --- |
| `datetime` | 委托时间 |
| `sym` | 股票代码 |
| `price` | 委托价格 |
| `size` | 委托数量 |
| `side` | 买卖方向，`1` 为买，`-1` 为卖 |
| `orderid` | 委托编号 |

`trade` 文件记录逐笔成交或撤单。常用字段包括：

| 字段 | 含义 |
| --- | --- |
| `datetime` | 成交或撤单时间 |
| `price` | 成交价格，撤单记录常为 0 |
| `size` | 成交或撤单数量 |
| `bidorderid` | 买方委托编号 |
| `askorderid` | 卖方委托编号 |

撤单在数据里通常表现为只有一边 order id 大于 0，另一边为 0。代码会在 `09:26:00` 前把这些已撤销委托从集合竞价订单簿里剔除。

## 3. 撮合流程

代码按以下步骤复现开盘价：

1. 读取 `09:26:00` 前的委托。
2. 根据 trade 里的撤单记录删除已撤委托。
3. 买盘按价格从高到低、时间从早到晚排序。
4. 卖盘按价格从低到高、时间从早到晚排序。
5. 如果最高买价大于等于最低卖价，就可以继续撮合。
6. 每次撮合都消耗买卖双方较小的数量。
7. 撮合停止后，记录最后一次可撮合时的买方价格和卖方价格。
8. 在这两个价格之间按 0.01 元生成候选开盘价。

## 4. 候选价如何计算

对每个候选价 `p`，计算：

```text
buy_vol  = 价格 >= p 的买入申报累计数量
sell_vol = 价格 <= p 的卖出申报累计数量
match_volume = min(buy_vol, sell_vol)
diff = abs(buy_vol - sell_vol)
```

这里的 `diff` 是项目最重要的字段之一。

## 5. “未成交量最小”的正确理解

容易误解的地方是“未成交量最小”。

一开始很容易把它理解为：

```text
低于候选价的买单数量 + 高于候选价的卖单数量
```

但在交易所集合竞价规则中，更符合实际撮合含义的是比较候选价附近的买卖累计申报数量差：

```text
未成交量最小 = abs(buy_vol - sell_vol)
```

也就是说，重点不是把所有价外订单机械相加，而是看在候选价上，买卖两边累计可成交意愿的失衡程度有多小。

本项目代码中用 `diff` 表示这个量。

## 6. 深市规则

深市候选价筛选顺序：

1. 选可实现最大成交量的价格；
2. 如果多个价格成交量相同，选 `diff` 最小；
3. 如果 `diff` 仍相同，开盘集合竞价取最接近前收盘价的价格；
4. 如果距离前收盘价也相同，取较高价格。

## 7. 沪市规则

沪市的并列处理与深市不同。

本项目复现 notebook 中验证过的逻辑：

1. 如果所有有效候选价的 `diff` 都为 0，则取候选价区间的中间价，并按 0.01 元四舍五入。
2. 如果候选价中存在非 0 的 `diff`，则取候选价区间的首尾价格比较：
   - 选择首尾中 `diff` 更小的一边；
   - 如果首尾 `diff` 相同，则取首尾中间价。

这也是让 `false sym35` 中沪市边界样本全部命中的关键。

## 8. 集合竞价失败时怎么办

部分样本在集合竞价阶段无法形成可撮合订单。例如最高买价始终低于最低卖价。此时项目按原 notebook 的逻辑，用连续竞价第一笔有效成交价作为开盘价兜底。

这类样本会在结果中标记为：

```text
status = fallback_continuous
```
